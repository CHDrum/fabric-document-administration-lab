# Fabric Document Administration Lab Guide

Build in order. Each module includes an observable checkpoint and an answer key. The source schemas and rules are deliberately synthetic; do not upload real documents or connect production systems.

| Module | Minutes | Outcome |
| --- | ---: | --- |
| [00 - Start and scope](00-start.md) | 10 | Correct tenant, capacity, workspace and business boundary |
| [01 - Land the snapshot](01-landing.md) | 25 | Six CSVs and empty Warehouse schema |
| [02 - Build ingestion](02-ingestion.md) | 25 | Six sequential, repeatable copies |
| [03 - Publish products](03-products.md) | 25 | Current catalog, history, cost and review buckets |
| [04 - Model and report](04-report.md) | 30 | Explicit model and three report pages |
| [05 - Validate and replay](05-validate.md) | 10 | Exact answer checks and stable replay |
| [06 - Wrap up](06-wrap-up.md) | 5 | Handoff, next steps and safe cleanup |
| **Total** | **130** | |

Before the workshop clock starts, the tenant administrator should enable the required Fabric workloads, assign an approved capacity, confirm individual author/viewer licenses, and verify repository access. Pairing reduces setup friction; it is not evidence that a particular capacity can support every learner concurrently.
